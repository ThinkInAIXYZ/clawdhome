# ClawdHome 统一设计语言与界面语言风格指南

本指南作为 ClawdHome 项目官方的设计与文案规范，旨在约束和统一应用内所有视图组件的**视觉表现力**与**界面语言风格（文案）**，确保产品呈现出苹果原生的精致感、AI 时代的灵动感与高度的专业度。

---

## 第一部分：界面文案与语言风格规范 (Linguistic & Tone Guidelines)

界面文案（语言风格）是用户与软件交互的心灵通道。好的文案应该像一位专业、冷静又温暖的私人助理。

### 1. 动作导向型文案 (Action-Oriented Verbs)
界面上的按钮、卡片操作区、链接文字等**可交互元素**，应避免使用被动陈述或无场景感的机械指令。
* ❌ **不推荐**：“打开”、“点击此处”、“去设置”、“确定”、“查看”。
* ✅ **推荐**：使用更有代入感的**主动动词短语**：
  * “打开（语音转文字工具）” ➡️ **“立即开启” / “开始转录”**
  * “去设置（配置模型）” ➡️ **“管理模型配置” / “管理实例”**
  * “保存” ➡️ **“保存并应用”**
  * “确定（删除用户）” ➡️ **“确认移除”**

### 2. 精细化状态与生命力表达 (Vitalized Status mapping)
对于服务、实例和工具的当前状态，避免使用冷冰冰的、单一的系统状态字眼。尽量细分状态，并赋予文字活力的隐喻。
* ❌ **不推荐**：“可用”、“不可用”、“敬请期待”、“已关闭”。
* ✅ **推荐**：
  * **已就绪 / 立即体验 (Ready / Active)**：表示工具或服务已部署完成，处于高可用状态。
  * **研发中 (In Dev)**：表示核心功能已在开发迭代，即将进入测试。
  * **规划中 (Planned)**：表示功能已列入路线图，设计阶段已启动。
  * **待装载 (Deployable)**：表示环境已就绪，用户只需一键初始化即可拉起服务。
  * **离线中 / 已挂起 (Suspended / Offline)**：表示因主动或被动原因处于静止状态，支持唤醒。

### 3. 国际化自适应与长度预算 (i18n Balance & Footprint)
ClawdHome 是双语应用，英语往往比中文占用更多的显示宽度（CI 会检测标签的中文和英文宽度比，当英文 > 中文 × 2 时触发警告）。
* **严格的长度预算**：
  * 分段选择器 (Segmented Tab) 选项：**英文 ≤ 12 字符**，**中文 ≤ 4 汉字**。
  * 表单标签 (Field Label) / 按钮：**英文 ≤ 14 字符**，**中文 ≤ 6 汉字**。
  * 表格表头：**英文 ≤ 16 字符**，**中文 ≤ 8 汉字**。
* **简洁文法**：
  * 丢弃冠词与不必要的介词（如用 `Pool` 替代 `From Global Pool`）。
  * 英文词汇优先使用**名词或动词单字**，避免长句做标签（如用 `Source` 替代 `Configuration Source Picker`）。
* **标点符号对称**：中文使用“…”时，英文必须对应使用“...”。

### 4. 专业与同理心的情感基调 (Empathetic & Professional)
* 绝对不要将底层的原始报错堆栈（例如 `posix error 13: permission denied`）直接抛给非技术用户。
* 出错或需要权限时，应使用温暖且解释原理的语言：“ClawdHome 正在为您构筑沙盒边界，请在系统设置中授予相应辅助功能权限以继续。”

## 第二部分：视觉设计系统约束 (Visual Design Guidelines)

为了让应用界面充满呼吸感和高级质感，我们统一规范了四大视觉支柱。

### 1. 情感渐变主题 (Emotional Color Gradients)
不同的业务域应具备其专属的情感标志渐变色，而不是单一的、平淡的系统原生色：
* **声音与转译**：`Blue -> Purple`（蓝紫渐变），代表电波的深邃与智慧。
* **翻译与语言互译**：`Emerald -> Teal`（翡翠青绿渐变），代表沟通与流畅。
* **多模态与视觉识别**：`Orange -> Coral`（琥珀橘红渐变），代表光影与发现。
* **文字与结构化提炼**：`Teal -> Royal Blue`（黛绿深蓝渐变），代表逻辑与沉淀。
* **等待与未就绪状态**：`Neutral Slate Gray`（石板冷灰），代表沉稳与孕育。

### 2. 软质玻璃拟态 (Soft Glassmorphism)
卡片组件不应使用生硬粗糙的原生 GroupBox。我们统一使用如下层次的玻璃卡片设计：
* **底色**：系统背景色 + 极轻微的白光叠层（亮色模式下）或微弱的暗灰光泽（暗色模式下）。
* **描边 (Inner Border)**：`1px` 的微弱半透明描边（`Color.white.opacity(0.12)` 或 `Color.secondary.opacity(0.1)`），模拟精致的玻璃切割边缘。
* **阴影**：带有色相扩散的极弱渐变阴影（如 `Color.black.opacity(0.06)`），营造优雅的悬浮感。

### 3. 悬浮微动交互 (Hover Micro-interactions)
所有可交互的卡片和按钮在鼠标滑过（Hover）时，都必须产生细腻的物理反馈：
* **尺寸变化**：轻微拉伸缩放（`scaleEffect(1.02)`），伴随 `0.2` 秒缓动弹簧动画。
* **阴影与光效**：卡片的阴影半径随 hover 增加，渐变背景饱和度微增，产生迎光面变亮的视觉差。

### 4. 状态发光呼吸徽章 (Glowing Status Badges)
状态的传达可以通过精美的小指示灯组件来完成：
* **就绪状态**：绿色的发光指示点，配合轻微的呼吸动画（闪烁透明度在 `0.6` 到 `1.0` 之间）。
* **建设中状态**：柔和紫光或金黄色指示点。
* **规划中状态**：石板冷灰色指示点，静谧内敛。

## 第三部分：SwiftUI 代码样板参考

开发者应当复用 `DesignSystem.swift` 中提供的统一组件。

### 1. 微动交互卡片样板
```swift
struct MyFeatureCard: View {
    var body: some View {
        VStack {
            Text("组件标题")
            Text("组件副标题")
        }
        .premiumCard(theme: .blueTheme, isClickable: true) {
            // 点击后的动作
        }
    }
}
```

### 2. 状态徽章样板
```swift
// 已就绪呼吸灯
PremiumStatusBadge(style: .ready)

// 研发中
PremiumStatusBadge(style: .inDevelopment)
```
